# V10 Web 可视化版设计

状态：已确认
日期：2026-07-19
基础版本：V9 流量治理、故障隔离与服务降级版

## 1. 背景

V1 到 V9 已经完成从本机 WebSocket 广播到 Redis、Kafka、MySQL，以及限流、熔断、降级和故障恢复的逐步学习。

目前主要交互仍在 CLI 中完成，存在三个问题：

1. 多客户端发送和接收弹幕不够直观。
2. V9 已有的限流、熔断和投递指标只能通过日志或 JSON 查看。
3. 后续加入 AI 后，缺少适合展示审核、摘要和语义搜索结果的产品界面。

V10 的目标是把现有后端能力组织成一个真实可用的浏览器体验，同时保留工程学习价值。

## 2. 目标

V10 必须完成：

1. 浏览器加入房间、发送弹幕、接收广播和点赞。
2. 弹幕同时显示在直播画面覆盖层和实时消息列表中。
3. 展示房间在线人数、点赞数和连接状态。
4. 展示进程连接数、消息投递、入口丢弃、限流、慢客户端、Redis 和 Kafka 状态。
5. 展示一条弹幕从浏览器到 MySQL 的完整链路说明。
6. 支持不使用 Redis、Kafka、MySQL 的本机演示模式。
7. 中间件恢复后，无需修改前端即可切换到完整链路模式。
8. 为后续 AI 审核、摘要和语义搜索预留独立页面入口。

## 3. 非目标

V10 不实现：

1. 视频推流、转码、HLS 或 WebRTC。
2. 登录注册、JWT 鉴权和真实主播管理。
3. 历史弹幕查询。
4. MySQL 健康检查聚合。
5. Prometheus、Grafana 或分布式链路追踪。
6. AI 审核、摘要和语义搜索。
7. 正式生产部署。

直播舞台使用本地位图作为演示画面，只承载真实弹幕覆盖层，不伪装成视频播放能力。

## 4. 核心决策

### 4.1 版本组织

新增独立的 `v10/`，以 V9 为基础复制并更新包路径、资源名称和学习文档。

这样做符合现有 V1 到 V9 的学习方式：

- V9 保持不变，便于回看基建版本。
- V10 可以单独运行和测试。
- 后续 AI 从 V10 的浏览器体验继续演进。

### 4.2 前端技术

前端使用：

- React
- TypeScript
- Vite
- React Router
- Lucide 图标
- Recharts
- 原生 CSS 和设计变量

不引入 Redux、Tailwind 或大型组件库。当前状态规模较小，使用组件状态和自定义 Hook 更容易学习，也能减少与 Go 主线无关的复杂度。

### 4.3 同源接入

开发模式：

```text
浏览器 -> Vite 开发服务器
             ├── /ws      -> Go :8080
             ├── /metrics -> Go :8080
             └── /health  -> Go :8080
```

生产演示模式：

```text
npm run build
Go server -web-dir ./v10/web/dist
浏览器与 Go 服务同源
```

Vite 通过代理连接 Go，构建后由 Go 托管静态文件，因此不需要新增宽松 CORS 配置。

### 4.4 不修改实时协议

V10 继续使用 V9 的协议：

| 类型 | 方向 | 作用 |
|---|---|---|
| `101` | 双向 | 发送或接收弹幕 |
| `102` | 服务端到客户端 | 房间在线人数和点赞数 |
| `103` | 客户端到服务端 | 点赞 |
| `104` | 服务端到客户端 | 限流、过载和内容过长反馈 |

WebSocket 地址：

```text
/ws?uid=<用户编号>&name=<昵称>&room=<房间编号>
```

### 4.5 不伪造依赖状态

V9 服务端能够观测 Redis 和 Kafka Producer，但不能观测独立 Consumer 进程中的 MySQL。

因此 V10：

- Redis 和 Kafka 显示真实状态。
- 无中间件时显示 `disabled`，不显示成故障。
- MySQL 显示“当前接口不可观测”。
- 不根据 Kafka 正常推断 MySQL 正常。

## 5. 页面结构

### 5.1 全局外壳

顶部固定包含：

- 产品名 `DANMAKU LAB`
- WebSocket 连接状态
- 当前用户和房间
- 直播间、运行监控、链路说明三个页签

用户首次进入时生成本地用户编号和默认昵称，并进入 `room-01`。用户可以在顶部切换昵称和房间；切换时先关闭旧连接，再建立新连接。

### 5.2 直播间

桌面端：

```text
┌────────────────────直播舞台────────────────────┬────实时弹幕────┐
│ 本地演示画面                                    │ 消息列表       │
│ 真实弹幕覆盖层                                  │ 控制反馈       │
│ LIVE / 房间 / 在线人数                          │ 输入框         │
├────────在线────点赞────连接状态────本次消息────┤ 点赞 / 发送    │
└────────────────────────────────────────────────┴────────────────┘
```

移动端：

- 直播舞台在上，实时弹幕在下。
- 指标改为两列。
- 输入区保持可见但不使用固定定位，避免遮挡消息。

直播间状态来源：

- 弹幕：WebSocket `type=101`
- 在线和点赞：WebSocket `type=102`
- 限流和过载：WebSocket `type=104`
- 连接状态：浏览器 WebSocket 生命周期

### 5.3 运行监控

顶部展示：

- 当前连接数
- 每秒投递数
- 入口丢弃数
- 用户和房间限流数

主体展示：

- 最近 60 秒投递与限流趋势
- Redis 熔断状态
- Kafka Producer 健康状态
- 慢客户端丢弃和断开数量
- goroutine 和内存信息
- 当前浏览器会话内推导出的治理事件

指标每 2 秒读取一次 `/metrics`。每秒投递等速率值通过相邻两次累计值之差除以时间差计算。

“最近治理事件”不是伪造的后端日志，而是前端根据真实指标变化生成的会话内事件，例如：

- 用户限流累计值增加
- Redis 熔断状态变化
- Kafka 状态变化
- 慢客户端断开累计值增加

事件不持久化，刷新页面后清空。

### 5.4 链路说明

该页面展示：

```text
浏览器
  -> WebSocket 校验与限流
  -> Manager 房间广播
  -> Redis 跨实例同步 / 本机降级
  -> Kafka 异步持久化
  -> Consumer 批量消费与恢复
  -> MySQL 幂等落库
```

链路节点可使用当前真实状态着色：

- 正常：绿色
- 降级或限流：黄色
- 故障：红色
- 未启用或不可观测：灰色

### 6.1 `useDanmakuSocket`

负责：

- 构造 WebSocket 地址
- 建立和关闭连接
- 解析消息包
- 维护连接状态
- 指数退避重连
- 发送弹幕和点赞
- 切换用户或房间

连接状态：

```text
connecting -> connected -> reconnecting -> offline
```

重连等待从 500 毫秒开始，逐步增加，最大 10 秒。用户主动切换房间或退出时不触发旧连接重连。

### 6.2 `useMetrics`

负责：

- 每 2 秒读取 `/metrics`
- 保留最后一次成功快照
- 保存最近 30 个采样点，即约 60 秒
- 从累计值计算速率
- 区分 `healthy`、`degraded`、`disabled` 和 `stale`

请求失败时保留旧数据并标记过期，不把所有指标重置为零。

### 6.3 `useMetricEvents`

比较前后两次指标：

- 计数器增加时生成增量事件。
- 熔断器或 Kafka 状态改变时生成状态事件。
- 最多保存 50 条事件。
- 相同采样周期内的同类事件合并。

### 6.4 弹幕轨道

弹幕覆盖层使用有限轨道：

- 桌面最多 8 条轨道。
- 手机最多 4 条轨道。
- 同一轨道上一条弹幕离开安全区域后才能复用。
- 活跃飘屏最多 40 条。
- 聊天消息列表最多 300 条。

这些限制避免高流量时 DOM 节点无限增加，并减少文字重叠。

## 7. 后端改动

V10 后端保持 V9 的并发、限流、Redis、Kafka 和 MySQL 行为。

新增范围只包括：

1. 将包路径和资源名称更新为 V10。
2. `cmd/server` 增加可选 `-web-dir`。
3. 当 `web-dir` 中存在构建结果时，根路由托管静态文件。
4. 前端路由使用 SPA fallback，未知非 API 路径返回 `index.html`。
5. `/ws`、`/metrics` 和 `/health` 优先级高于静态文件。
6. 静态目录不存在时，Go 服务仍可作为纯后端正常启动。

不向 Manager、Redis worker、Kafka Publisher 或 Consumer 热路径加入前端逻辑。

## 8. 异常处理

| 场景 | 前端行为 |
|---|---|
| 首次连接失败 | 显示离线状态和立即重试按钮 |
| 连接意外断开 | 指数退避重连，保留已有消息 |
| 切换房间 | 先关闭旧连接，清理旧房间飘屏，再连接新房间 |
| `rate_limited` | 显示范围和倒计时，倒计时内禁用对应操作 |
| `server_overloaded` | 明确显示服务过载，不追加“发送成功”消息 |
| `content_too_long` | 保留输入并提示 200 字限制 |
| `/metrics` 失败 | 保留旧值，标记数据已过期 |
| Redis disabled | 显示未启用，直播间继续本机广播 |
| Redis degraded | 显示降级，本机广播仍可使用 |
| Kafka disabled | 显示未启用，不宣称历史已保存 |
| Kafka degraded | 显示持久化风险，不影响实时连接 |
| 未知 WebSocket 消息 | 忽略并记录开发日志，不使页面崩溃 |

## 9. 视觉与交互

采用已确认的“信号控制台”风格：

- 白色和浅灰作为应用表面。
- 近黑色作为直播舞台和高强调操作。
- 信号红表示直播与关键弹幕。
- 健康绿表示正常依赖状态。
- 告警黄表示限流、降级和过期数据。
- 卡片圆角不超过 8px。
- 工具按钮优先使用 Lucide 图标。
- 不使用装饰性渐变、光球或营销式大标题。
- 直播间是首屏，页面不增加介绍型落地页。

舞台使用一张本地位图作为真实视觉资产，弹幕覆盖层位于其上。位图不包含生成文字，避免文字失真。

## 10. 测试设计

### 10.1 Go

执行：

```bash
go test -count=1 ./v10/...
go test -race -count=1 ./v10/internal/...
go vet ./v10/...
```

新增静态文件处理测试：

- API 路由不被 SPA fallback 覆盖。
- 静态资源按原路径返回。
- 前端路由回退到 `index.html`。
- 静态目录缺失时后端仍可启动。

### 10.2 前端单元测试

使用 Vitest 和 React Testing Library，至少覆盖：

- 四类消息包解析。
- 非法 JSON 和未知类型处理。
- 控制消息映射。
- 指标差分和计数器重置。
- 指标过期状态。
- 重连退避和主动关闭。
- 消息、事件和飘屏数量上限。

### 10.3 浏览器功能测试

使用 Playwright：

1. 启动无中间件 Go 服务。
2. 启动 Vite 或构建后的静态页面。
3. 两个浏览器进入同一房间。
4. 浏览器 A 发送，A 和 B 都收到。
5. 浏览器 B 点赞，双方收到统计更新。
6. 高频发送触发限流，页面显示倒计时。
7. 打开运行监控，指标随流量变化。
8. 切换房间后不再收到旧房间消息。

### 10.4 视觉测试

检查：

- 桌面 `1440x900`
- 平板 `1024x768`
- 手机 `390x844`

验证：

- 文本不溢出。
- 弹幕不遮挡顶部房间信息。
- 输入区不遮挡消息。
- 指标在窄屏正确换行。
- 图表和依赖状态不出现空白。

### 10.5 Docker 集成测试

Docker Desktop 已安装，但当前引擎仍等待 macOS 管理员授权。

授权完成后补充：

1. Redis 跨实例广播。
2. Redis 故障熔断和恢复。
3. Kafka 生产与消费。
4. MySQL 批量落库。
5. MySQL 故障时分区暂停和恢复。
6. 页面展示 Redis/Kafka 真实状态变化。

在这些测试实际执行前，文档不得宣称完整容器链路通过。

## 11. 验收标准

V10 完成需要同时满足：

1. 无中间件模式下，两个浏览器可以互发弹幕和点赞。
2. 弹幕覆盖层和消息列表均显示真实消息。
3. 服务端控制消息能够转化为明确的页面反馈。
4. 运行监控只显示真实或明确不可观测的状态。
5. 页面长时间运行时消息、事件和图表样本均有数量上限。
6. 桌面和手机页面无明显遮挡或溢出。
7. Go 测试、竞态检测、静态检查和前端测试通过。
8. Playwright 核心流程通过。
9. V10 README 能解释目录、协议、前端状态管理、测试方式和 V9 到 V10 的变化。

## 12. 后续 AI 接口

V10 不实现 AI，但页面结构预留后续扩展：

```text
直播间
运行监控
链路说明
AI 洞察（V11）
```

AI 页面必须通过独立异步链路读取审核或摘要结果，不能让模型调用进入 WebSocket 发送和广播热路径。
